The player DB — answering your main question

Yes, completely doable. ~10 teams × ~25 squad players = ~250 rows total — trivial for SQLite. Team selection auto-filters players via a team_id FK on the players table. The real question isn't feasibility, it's how we handle the edge cases below.

✓ Easy path

Seed marquee players first

Start with ~15 top players per team (captains, openers, main bowlers). Wikipedia has solid headshots for every IPL star. Covers 90% of contracts you'll actually create.

Fallback

"+ Add player" inline

If the player you want isn't in the filtered list, the last grid cell is a "+ Add" tile. Small modal: name · role · optional headshot upload. Saves to DB, appears in the list immediately. No second admin screen needed.

Graceful degradation

No headshot? Initials on team colour

A player added without a headshot renders as initials on the team's primary colour (same treatment as the placeholder cells in State B above). Card still looks consistent — no broken images ever.

Seasonal refresh

Squads change each IPL auction (roughly Dec–Jan each year). Plan: a one-off admin script run before each season that updates team_id for players who moved and marks retired players is_active=0. Not a weekly chore.

What has to change under the hood

DB schema additions

CREATE TABLE teams (
  id INTEGER PRIMARY KEY,
  name TEXT, short_code TEXT UNIQUE,
  primary_colour TEXT,
  logo_path TEXT                 -- '/logos/csk.svg'
);

CREATE TABLE players (
  id INTEGER PRIMARY KEY,
  name TEXT, slug TEXT UNIQUE,
  team_id INTEGER REFERENCES teams(id),
  role TEXT,                     -- batter | bowler | all-rounder | wk
  headshot_path TEXT,            -- '/players/dhoni.jpg' or NULL
  is_active INTEGER DEFAULT 1
);
CREATE INDEX idx_players_team ON players(team_id);

ALTER TABLE contracts ADD COLUMN phase TEXT;           -- over | by_over | toss | match
ALTER TABLE contracts ADD COLUMN subject_kind TEXT;    -- team | player | matchup | match_generic
ALTER TABLE contracts ADD COLUMN team_id INTEGER REFERENCES teams(id);
ALTER TABLE contracts ADD COLUMN opponent_team_id INTEGER REFERENCES teams(id);
ALTER TABLE contracts ADD COLUMN player_id INTEGER REFERENCES players(id);

Existing contract types — kept, extended, renamed

  • Kept: runs_over, wicket_over, team_total, batsman_milestone, boundary_over, manual
  • New: toss_winner, match_winner, player_match_stat (e.g. "Bumrah takes a wicket today")
  • manual stays — it's the escape hatch for anything we don't model

New API endpoints

  • GET /api/teams — 10 rows, cached on client; powers team picker
  • GET /api/players?team_id=...&q=... — filtered + searchable; powers player picker
  • POST /api/players (admin only) — inline "Add player" from the create form

Seed data (one-time)

  • 10 teams — full name, short code, primary colour, logo path. Logos already downloaded to client/public/logos/.
  • ~150 players to start (15/team × 10 teams). Wikipedia headshots for marquee names, initials fallback for the rest. Downloader script similar to what we used for Dhoni/Kohli/Bumrah earlier.

Form rewrite in Admin.jsx

  • Phase tiles → Type tiles → Subject pickers → Params (phase- and type-dependent reveal)
  • New TeamGrid component — 10 logo cells, single-select
  • New PlayerGrid component — takes teamId, searchable, "+ Add" last cell
  • New MatchupAuto component — read-only, pulls from active match
  • Existing ContractPreview replaced with live render of the new card
  • Admin still keeps Save as Draft / Publish Now — no change to that flow

Build sequence (if you approve)

  1. DB + seeds — teams table, players table, seed 10 teams + 15 marquee players/team
  2. API endpoints — /teams, /players (GET + POST), simple & cached
  3. Card component — rewrite ContractCard.jsx to the new 3-slot layout using team/player joins
  4. Admin form — TeamGrid, PlayerGrid, phase/type tile flow, live preview
  5. Migration — backfill existing contracts' phase/subject_kind/team_id from their current type + condition_json
  6. Cut-over — old Admin form retired once the new one is verified
